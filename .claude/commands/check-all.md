คุณคือ QA engineer ของ Geek Pop-up POS งานนี้คือ **ตรวจ** ให้ละเอียดที่สุด หาบั๊กให้เจอก่อนพนักงานและลูกค้าเจอ ไม่ใช่พิสูจน์ว่าโค้ดถูก

ขอบเขต: $ARGUMENTS (ว่าง = ทุกหมวด)

## ขั้นตอน

1. **อ่านก่อน**: `CLAUDE.md`, `docs/business-rules.md`, `docs/qa-checklist.md`, โค้ดใน `app/` ที่เกี่ยวกับหมวดที่ตรวจ และเทสต์เดิมใน `tests/` (ดูว่าข้อไหน "มีเทสต์แล้ว" จริง)
   - ค่าที่คาดหวังยึด **business-rules.md** เสมอ ถ้า checklist กับ business-rules ไม่ตรงกัน ให้ยึด business-rules แล้วแจ้งว่า checklist ต้องแก้

2. **บอก Tee สั้นๆ** ว่าจะตรวจหมวดไหน จะติดตั้งอะไรเพิ่ม แล้วเริ่มเลย ไม่ต้องรออนุมัติ (ยกเว้นต้องแก้โค้ดใน `app/` ซึ่งห้ามทำในงานนี้)

3. **หมวด 0** รันคำสั่งจริงทุกข้อ (`npm test`, `git status`, grep) เก็บ output จริงเป็นหลักฐาน

4. **หมวดที่เป็น A เขียนเป็นเทสต์อัตโนมัติ** ไว้ใน `tests/qa/*.test.js`
   - ใช้รูปแบบเดียวกับเทสต์เดิม: jsdom เปิด `prototype/pos.html` (หรือ vm เปล่าสำหรับฟังก์ชันล้วนแบบ `tests/app/pricing.test.js`), เข้าระบบด้วย `tests/auth-helper.js`, พิมพ์ `PASS ชื่อ` / `FAIL ชื่อ ...`
   - ลงทะเบียนไฟล์ใหม่ใน `tests/run-tests.js` ให้ `npm test` รันด้วย
   - ชื่อทุกเทสต์ขึ้นต้นด้วยรหัส เช่น `P07 Greek 89 + กล้วย×3 + มะม่วง + กราโนล่า = 114`
   - ค่าคาดหวังคิดเองจาก business-rules.md **ห้ามคัดลอกผลจากโค้ดมาเป็นค่าคาดหวัง**
   - P27 / R02 / H01: เขียนฟังก์ชันอ้างอิงใหม่จาก business-rules.md (ห้าม import `priceItem`, `promoEval`, `buildReport`) สุ่มด้วย seed คงที่ ถ้าไม่ตรงให้พิมพ์ seed + ออเดอร์ที่ทำให้ไม่ตรง
   - เวลา: จำลองนาฬิกา (ดูวิธีใน `tests/prototype/demo-business-round.test.js`) สำหรับ 22:59 / 23:00 / ข้ามเดือน / ข้ามปี
   - **เทสต์ที่เจอบั๊กจริง**: พิมพ์ `KNOWN-BUG รหัส ...` (ห้ามมีคำว่า FAIL ในบรรทัดนั้น เพราะ runner นับคำนั้น) เพื่อไม่ให้ `npm test` แดงจนบังเทสต์อื่น แต่ต้องอยู่ในรายงานทุกตัว
   - ห้ามแก้เทสต์เดิมให้ผ่าน ถ้าเทสต์เดิมพัง = รายงาน

5. **ทดสอบผ่านเบราว์เซอร์จริง** (UI01, UI02, C06, E01) ด้วย Playwright + Chromium
   - ติดตั้งเป็น devDependency (`npm i -D playwright` แล้ว `npx playwright install chromium`) และเพิ่มสคริปต์ `"qa:e2e"` ไม่ใส่ใน `npm test` (ช้า)
   - เปิด `prototype/pos-demo.html` (รหัส DEMO เจ้าของ 1234 · พนักงาน 1111) viewport 1280×800 และ 800×1280 เปิด touch
   - stub `window.print`, เก็บ console error, ถ่าย screenshot จุดสำคัญไว้ `docs/qa/screens/YYYY-MM-DD/` (เพิ่ม `docs/qa/screens/` ใน `.gitignore`)

6. **ข้อที่เป็น M** อย่าเดาผล ใส่สถานะ `ต้องทดสอบด้วยคน` พร้อมขั้นตอนสั้นๆ ที่ Tee ทำตามได้บนแท็บเล็ต

7. **เขียนรายงาน** `docs/qa/report-YYYY-MM-DD.md` (ภาษาไทย)
   ```
   # รายงานตรวจ POS — <วันที่> · commit <hash> · sw VERSION <...>
   ## สรุป 3 บรรทัด
   พร้อมใช้ / ยังไม่พร้อม เพราะ ... · S1 x · S2 x · S3 x
   ## บั๊ก (เรียงจากรุนแรงสุด)
   | รหัส | ระดับ | อาการ | วิธีทำให้เกิด | คาดหวัง | ได้จริง | ไฟล์:บรรทัด | แนวทางแก้ |
   ## คำถามที่ Tee / เจ้าของร้านต้องตัดสิน
   ## ความเสี่ยงที่รู้แล้ว (ยอมรับได้หรือต้องตัดสินใจ)
   ## ผลทุกข้อ
   | รหัส | ผ่าน / ไม่ผ่าน / known bug / มีเทสต์เดิมผ่าน / ต้องทดสอบด้วยคน / ข้าม | หลักฐาน (ชื่อเทสต์ / output / screenshot) |
   ## ตรวจไม่ได้ เพราะอะไร
   ## checklist ที่ควรแก้ (ถ้ามี)
   ```

8. **จบด้วยข้อความสั้นถึง Tee** (ภาษาไทยง่ายๆ): พร้อมใช้หรือยัง, บั๊ก S1/S2 กี่ข้อ, 3 อย่างที่ควรแก้ก่อน แล้วถามว่าจะให้แก้ข้อไหน

## กฎ

- **ห้ามบอกว่า "ผ่าน" ถ้าไม่ได้รันจริง** ทุกข้อที่ผ่านต้องมีหลักฐาน
- **ห้ามแก้โค้ดใน `app/`, `prototype/`, `manual/`, `printer-test/` ระหว่างตรวจ** — รายงานแล้วรอ Tee สั่ง · แก้ได้เฉพาะ `tests/`, `docs/qa/`, `docs/qa-checklist.md` (เพิ่มรหัสใหม่), `package.json` (devDependency + สคริปต์ qa), `.gitignore`
- ถ้าโค้ดกับ business-rules.md ไม่ตรงกัน **อย่าเดาว่าอันไหนถูก** ใส่ในหมวดคำถาม
- ข้อที่ติด ⚠️ ใน checklist ให้รายงานพฤติกรรมจริงเป็น "คำถาม" หรือ "ความเสี่ยงที่รู้แล้ว" ไม่ใช่บั๊ก
- ห้ามแตะข้อมูลขายจริง ใช้ jsdom หรือ browser profile ใหม่ หรือ key DEMO เท่านั้น
- **repo เป็น public**: ห้ามใส่เลข PromptPay จริง รหัสจริง ยอดขายจริง ในเทสต์ รายงาน หรือ screenshot (ใช้ DEMO)
- เจอบั๊กหรือกรณีเสี่ยงที่ checklist ยังไม่มี → เพิ่มรหัสใหม่ท้ายหมวด (เช่น P29) ทั้งใน checklist และรายงาน
- ไม่ commit / push เว้นแต่ Tee สั่ง
- ก่อนส่งรายงาน รัน `npm test` ครั้งสุดท้าย แนบบรรทัดสรุป และยืนยันว่า `app/` ไม่ถูกแก้ (`git diff --stat app/`)
