# QA Checklist — Geek Pop-up POS

ใช้ก่อนปล่อยเวอร์ชันใหม่ให้พนักงานใช้ทุกครั้ง · Claude Code ใช้ไฟล์นี้ผ่านคำสั่ง `/check-all`
ค่าที่คาดหวังทุกข้อมาจาก `docs/business-rules.md` (อัปเดต 12 ต.ค. 2569) ถ้ากติกาเปลี่ยน ต้องแก้ไฟล์นี้ด้วย

แต่ละข้อมี **รหัส** ให้อ้างในรายงาน · **ใคร**: **A** = ตรวจอัตโนมัติได้ (Claude Code) · **M** = ต้องคนลองบนแท็บเล็ต/ปริ้นเตอร์จริง
**มีเทสต์แล้ว** = มีเทสต์ใน `tests/` ครอบคลุมอยู่ ให้ยืนยันว่ายังผ่าน ไม่ต้องเขียนซ้ำ (เขียนเพิ่มเฉพาะกรณีที่ขาด)

ระดับความรุนแรง
- **S1 วิกฤต**: เงินผิด, บิลหาย/ซ้ำ, ข้อมูลยอดขายหาย, ขายต่อไม่ได้, ข้ามสิทธิ์เจ้าของได้ → ห้ามปล่อย
- **S2 สูง**: พิมพ์ไม่ออก/ผิด, รายงานไม่ตรง, พนักงานสับสนจนกดผิด → แก้ก่อนปล่อย
- **S3 กลาง**: ใช้ได้แต่ไม่สะดวก, ข้อความไม่ชัด, ความเสี่ยงที่โอกาสเกิดต่ำ
- **S4 ต่ำ**: ความสวยงาม
